튜토리얼 단일 함수 사용 가이드

무기 획득·전투·퍼즐 이벤트에서 DataAsset 튜토리얼을 최초 한 번만 표시

호출 함수 
UTutorialBlueprintLibrary::ShowTutorialOnce(
    WorldContextObject,
    TutorialId,
    TutorialStepData
);

선언: Source/Pragmata_2P/Game/TutorialBlueprintLibrary.h

구현: Source/Pragmata_2P/Game/TutorialBlueprintLibrary.cpp

1. 준비

  1. Content Browser에서 Miscellaneous → Data Asset 선택
  2. 클래스로 TutorialStepData 선택
  3. 제목, 이미지, 설명, 키 안내, Target Role 입력
  4. 호출부 클래스에 DataAsset 참조를 UPROPERTY로 노출
UPROPERTY(EditDefaultsOnly, Category="Pragmata|Tutorial")
TObjectPtr<UTutorialStepData> WeaponTutorialData;

2. C++ 호출

#include "Game/TutorialBlueprintLibrary.h"

// 서버가 무기 최초 획득을 확정한 직후 호출
UTutorialBlueprintLibrary::ShowTutorialOnce(
    this,
    TEXT("Weapon.FirstAcquired"),
    WeaponTutorialData
);
인자값역할
WorldContextObject보통 this현재 World와 GameState 탐색
TutorialIdWeapon.FirstAcquired영구 표시 이력 SaveGame 키
StepDataUTutorialStepData*이미지·제목·설명·키 안내·대상 역할

3. Blueprint 호출

Show Tutorial Once
World Context Object = Self
Tutorial Id = Weapon.FirstAcquired
Step Data = DA_Tutorial_WeaponsUse

C++ 함수와 같은 경로를 사용합니다. 별도 popup 생성이나 저장 로직은 추가하지 않습니다.

4. 호출 규칙

  • 무기 획득처럼 gameplay 판정이 필요한 이벤트는 server 확정 후 호출
  • server 호출은 Hugh/Diana peer에 multicast
  • client 호출은 해당 로컬 viewport만 처리
  • DataAsset의 Target Role과 local role이 일치할 때만 표시
  • popup 초기화 성공 후에만 TutorialId 저장
  • 역할 불일치 또는 UI 실패 시 저장하지 않아 다음 호출에서 재시도 가능
TutorialId는 배포 후 변경 금지. rename하면 새 튜토리얼로 취급되고, 다른 튜토리얼과 공유하면 둘 중 하나가 표시되지 않습니다.

5. 최초 무기 획득 예시

Server confirms weapon acquisition
  → ShowTutorialOnce(this, "Weapon.FirstAcquired", WeaponTutorialData)
  → each peer checks Target Role and local SaveGame
  → popup initialization succeeds
  → TutorialId saved locally
  → later calls ignored

6. 테스트

  • 첫 호출에서 DataAsset의 제목·이미지·설명 표시
  • 같은 실행의 두 번째 호출에서 미표시
  • 게임 재실행 후 같은 ID 호출에서 미표시
  • 다른 ID 호출은 정상 표시
  • 역할 불일치 호출 뒤 올바른 역할에서는 표시
  • 2-player PIE에서 server 호출이 양쪽 peer에 전달
